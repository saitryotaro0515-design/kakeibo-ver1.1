家計ラボ v1.1 — 残高管理機能アップデート
====================================

■ バージョンアップ前に必ずバックアップ
1. 現在公開している家計ラボを開く
2. 「設定」→「データ管理」→「JSONを保存」
3. 保存したJSONファイルは消さずに保管してください

■ GitHub Pages の既存アプリを更新（再登録・新規リポジトリ不要）
1. MacBookでGitHubの既存リポジトリ「kakeiboapp」を開く
2. Codeタブの「Add file」→「Upload files」
3. このZIPを解凍し、以下の7ファイルをリポジトリの「一番上の階層」にアップロード
   index.html / styles.css / app.js / sw.js / manifest.webmanifest / icon-192.png / icon-512.png
   ※ZIPそのもの、または外側のフォルダはアップロードしないでください
   ※README_使い方.txtは任意です
4. 「Commit changes」をクリック
5. 元のGitHub Pages URLをSafariで再読み込み（PWAは2回再起動／再読み込みが必要な場合があります）
6. 画面下のメニューに「残高」が表示されたら更新完了です

■ 既存の家計データ
このアップデートは従来と同じローカル保存キーを使います。
同じURL／同じブラウザ／同じ端末内の既存データは引き継ぐ設計です。
ただしデータは端末・ブラウザ・ホーム画面アプリごとに別保存の場合があるため、
必ずアップデート前にJSONバックアップを保存してください。
JSONからの復元では現在のデータを置き換えるため、誤って上書きしないでください。

■ 残高入力の方法
1. 下メニューの「残高」を開く
2. 三菱UFJ銀行、ゆうちょ銀行、現金、PayPay、Suica、NISA（評価額）の残高を入力
3. 「基準日」を確認し、「入力した残高をまとめて保存」を押す
4. 貯金口座など別の口座は「口座を追加」から登録できます

【基準日の考え方】
基準日を今日にすれば、今この時点の残高を登録できます。
登録前の明細は二重計上せず、登録後に新しく入力した今日の入出金は残高に反映します。
過去日を基準日にする場合は、その日の終了時点の残高を入力してください。
後から過去日の明細を追加した場合、基準日以前の取引は反映されません。

■ 残高に取引を連動させる
「＋ 収支を登録」を開き、対象口座を選んで明細を保存します。
支出：支払元の残高を減らす
収入：入金先の残高を増やす
資金移動：移動元を減らして、移動先を増やす（家計簿の収支にはカウントしない）
口座を「未指定」にした明細は従来通り収支分析にのみ使用されます。
カード払いは「引落日」が空欄の場合、残高に反映されません。
カード利用日と引落日を両方入力すると、月次収支は利用日、口座残高は引落日で反映します。
カード代金の引落を別途「支出」として二重登録しないでください。

■ 重要な制限
・AWSや外部サーバーは不要。データは各端末のブラウザ内に保存します。
・GitHubはアプリのプログラムのみ配信します。実際の家計記録をGitHubに入れないでください。
・iPhoneとMacの間は自動同期しません。移行にはJSONを使います。
・過去の銀行取引の自動取得や照合はできません。
・NISAや投資の残高は自動で時価更新されません。評価額を手入力してください。
・残高は、登録した基準残高と「口座が指定された明細」による推計値です。
・今回の更新版のロジックテストは実施済みですが、iPhone実機操作は未検証です。
